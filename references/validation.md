# 校验、恢复与交付

## 成功的不同层次

| 证据 | 能宣称什么 |
|---|---|
| 文件存在或进程退出为零 | 阶段命令已结束，尚未证明内容正确 |
| `pixel_validation.json` 为 PASS | 文件结构、元数据和规定的源像素抽样通过 |
| `qupath_validation.json` 为 PASS 且最终状态 QUPATH_VERIFIED | 指定版本 QuPath 实际读取了全分辨率、多区域、各通道与报告的金字塔层，验证了源像素抽样 |
| 最终状态 QUPATH_VERIFIED_WITH_READER_LIMITATION | 全分辨率、源 ROI 与全部可用层读取通过，但存在已验证、明确记录的读取器限制；必须同时交付 `reader_limitations`，不能称全部导出层都已被 QuPath 读取 |
| 另有实际 GUI 操作证据 | 可以额外说明在桌面窗口中打开；headless 结果本身不能证明这一点 |

QuPath 脚本记录读取器类、版本、尺寸、通道、标定、金字塔读取和 ROI 摘要。只有完整验证成功才发布最终文件名。失败文件使用 `image.pending.*`，不能作为已验收文件交付。

`--skip-qupath` 是用户明确接受的降级选项；最终状态为 `CONVERTED_NOT_QUPATH_VERIFIED`。事后补验不能通过直接编辑 status.json 实现：需要实际运行 QuPath 验证并提供单独记录，或在新目录完成完整流程。改变 skip 参数会改变运行指纹，不能强行复用原指纹。

## 保留与损失

OME-TIFF 检查基础维度、位深、已存在的物理标定、通道名称/顺序/颜色/波长字段，以及每通道空间抽样像素。SVS 检查 tiled BigTIFF、Aperio 描述、缩略图位置、金字塔、RGB、标定和像素抽样。全分辨率输出不做有损压缩；通用分支的缩小金字塔重新采样，KFB 分支直接保留支持的原生层。

原始 OME XML、读取器通道信息与 MRXS 的 Slidedat.ini 副本写在结果目录。未知、未暴露或不能映射的厂商字段不发明默认值。Label/macro、扫描仪私有注释和分析对象没有迁移保证。保留所有原始文件。

通用分支的大型切片源/目标比较使用抽样，测试套件的小图另做全基础层比较。KFB 分支则逐块比较每个保留原生层的全部逻辑像素，报告明确区分缺失填充值。只有实际记录支持时才能声称完成全像素校验；不能从技术读入成功推断具体分析方法有效。

KFBF 分支逐块核对每个独立通道的全部已记录基础层像素，并单独核对明确授权的缺失填充；随后比较 Zarr 与 OME-TIFF 的所有输出层。`kfbf_source_zarr_validation.json` 与 `pixel_validation.json` 必须同时通过。原生低分辨率层没有写入新文件，输出使用已记录的最近邻显示金字塔。源 JPEG 已有损失不会被逆转，未知空缺不代表零表达。

## 可恢复阶段

1. 通用分支由 `bioformats2raw` 生成完整 Zarr；KFBF 由严格读取器生成标准 TCZYX Zarr。读取回检通过后登记完成。KFB 明场读取原生图块直接进入第二步，不生成 Zarr。
2. 写入 TIFF/SVS，源像素与文件检查通过后登记完成。
3. QuPath 实际读入并比较，然后发布最终文件，计算 SHA-256。

使用同样参数加 `--resume`。恢复前重新读取源元数据、检查运行指纹及已完成文件。修改后的源清单、代码、参数、运行配置会被拒绝；使用新目录重新运行。失败阶段的输出保留为带 `.incomplete-` 的名称，后续从该阶段重做，不附加写入坏文件。

KFB 的 `pixel_validation.json` 记录逐块比较的各层结果以及完整缺失区域；只有用户指定 `--missing-pixels black` 才接受未记录区域的黑色显示值。有效源像素与缺失区域必须分别报告。

这不是分块断点续写：若第一阶段中途失败，必须重新生成 Zarr。已经通过的阶段可以重用并再验。重复恢复会保留坏文件，可能占用额外空间；说明哪些是失败产物，由用户授权后才清理。

`.running` 锁记录本次 PID，防止并发写同一目录。机器重启留下的锁需要核对进程和运行主机后再手工移除；不凭 PID 已不存在就删除其他运行数据。中断只终止本次启动的子进程组。原始切片不会删除或改名。

最终发布使用同文件系统硬链接实现不覆盖已有文件。工作文件系统不支持硬链接时，在大转换前返回 `UNSUPPORTED_FILESYSTEM`；选用 Linux ext4 等工作目录。若发布成功后、写最终记录前系统崩溃，会保留文件并要求检查；不能自动覆盖。最终文件和已完成记录中的哈希不符则拒绝恢复。

## 空间、性能与隐私

默认至少保留 10 GiB 可用空间，并保守要求四倍解压像素体积作为转换空间。并发默认 4，Java 堆默认 8 GiB；Agent 应按机器条件调整，不能假定所有服务器资源可独占。长转换需持续报告阶段，勿根据压缩输入大小估算准确耗时。

运行目录包含绝对源路径、原始元数据、预览、日志、通道信息和校验结果；可能有患者标识。公开问题报告仅分享脱敏错误和合成复现。Skill 自身没有遥测或切片上传接口，环境安装只访问官方分发渠道。

## 交付措辞

通用分支抽样验证通过：

> 🎉 转换完成！✅ 已通过 QuPath 实际读取验证（版本与模式见记录）。📂 文件：实际绝对路径。🔬 可以在 QuPath 中开始分析。原有通道数、顺序与位深保留，源像素抽样一致；全片逐像素检查未执行。

KFBF 已有完整像素验证记录时，将最后一句替换为：“全部通道的已记录基础层像素与源数据一致，缺失表示值已单独核对；QuPath 完成元数据、各通道和多区域抽样读取。”仍须说明具体缺失数量与显示金字塔重建情况。

未验证：

> 🟡 文件转换与像素抽样检查完成，QuPath 读取验证尚未完成。📂 文件：实际绝对路径。待处理：具体缺少的环境或失败阶段。

失败：说明具体缺失/失败及下一步，不庆祝，不将 `.pending` 文件描述为可分析最终结果。

KFB 读取器限制状态示例：

> ✅ 全分辨率、源 ROI 和 QuPath 可用金字塔层已读取通过。SVS 保留并核对了全部导出层，但 QuPath 0.6.0 没有单独显示末端 1×1 层；导出层数与可读层数分别见报告。缺失源像素按已确认策略显示为黑色，并附完整位置清单。

此例外仅针对 [KFB 文档](kfb.md)描述的、可复现的 QuPath 0.6.0 末端缩放率碰撞；其他层数或尺寸差异仍失败，不能直接改低预期层数。
